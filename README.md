# 股市直播（一期 · 本地验证版 · 三市场 · 体育氛围）

> 把盘面行情、异动榜、快讯，翻译成体育比赛解说的口吻，多人设切换，页面上做「伪直播」。  
> 覆盖 **A股 / 港股 / 美股**，按开盘时间自动轮值；休市时段播最近收盘市场的复盘。  
> 视觉走卧龙台 luxury 金墨象牙白设计系统（配色 token 锁死，不得私改）。

## 1. 职责一句话

采集 A 股/港股/美股真实行情 + 全球股指 + 财经快讯 → 转成解说词 → 渲染成一个可在浏览器双击打开的伪直播页面，用于验证「解说词像不像球赛」。

### 3.1 解说流的数据契约（V1.6.0 起，改渲染前必读）

**一条流 = 时间 + 正文 + 标的标签。** 三者各有唯一来源，不许在页面里二次发明：

| 元素   | 来源                                 | 规矩                                                                        |
| ---- | ---------------------------------- | ------------------------------------------------------------------------- |
| 时间   | **页面播出时的真实时刻**（JS `clockAt()`）     | 不是 `segments[].t`。`t` 是脚本内的「场次相对秒」，只在音频/进度条场景用；显示成 `00:10` 会被读成产生时间 → 已废止 |
| 正文   | `segments[].text`                  | 页面只做数字高亮（`hl()`），不改写                                                      |
| 标的标签 | `segments[].refs[]`（narrate.py 产出） | `[{code, name, pct, price, kind}]`，一段最多 3 个                               |

`refs` 的四条硬规矩：

1. **`code` 认不出就留空，绝不猜。** 指数 ticker 走 `IDX_TICKER` 白名单（公开常量）；A 股代码按首位定后缀（6→`.SH` / 0,3→`.SZ` / 4,8,9→`.BJ`，含北交所 920 号段）。表里没有的指数 → 不出标签。**猜错代码比没有代码更糟**——标签是给人核对行情用的。
2. **板块无 ticker**（东财 `gn_*` 不是行情代码）→ 标签只给「名称 + 涨幅」，并用 `板块` 小字标出为什么缺代码。
3. **涨红跌绿**（中国口径，`--up` / `--down`），无涨跌数据时给 `—` 不着色。
4. **行情是快照，不是逐笔。** 标签的 `pct` 与正文数字同源（同一份 `snapshot.json`），快照时刻写在标签 `title` 里，鼠标悬停可见。**不要在标签上写「实时」二字**——静态页没有行情通道，那是假的。要真·逐笔需后端，见 §6 第 15 条。

**已废止的显示元素**（V1.6.0，别加回来）：`segments[].tag` 的分类徽章（开场/收尾/快讯/资金…）、「正在播」角标、人物卡 `slogan` 行。`tag`/`ev` 字段**保留在 JSON 里**作诊断，页面不再渲染。

### 4.1 本地「直播循环」——看真实盘面效果用

单次构建出的是**快照**（数据冻在构建那一刻）。要像直播一样持续更新，用循环脚本：

```bash
cd /Users/yangxia/WorkBuddy/卧龙台/股市解说直播

# 「两档刷新」自动策略（V1.7.0）+ 数据驱动的交易日判定（V1.8.0）
#   开市常规交易 → 活跃档 120s；盘前/盘后/休市/节假日 → 平稳档 300s
nohup ./run_live.sh >logs/loop_boot.log 2>&1 & disown

# 也可强制：SPEED=active|calm 覆盖自动选档；或传数字 ./run_live.sh 180
# A 股全市场采集：默认 COLLECT_CN=auto（仅当 A股今日确有行情时才采，并强制平稳档护东财）
#   COLLECT_CN=1 强制采（调试）；COLLECT_CN=0 永不采

# 起一个静态服务（页面用相对路径引 vendor/，必须走 http，别用 file://）
nohup python3 -m http.server 8776 --bind 127.0.0.1 >logs/http.log 2>&1 & disown
# 打开 http://127.0.0.1:8776/live.html

# 停
pkill -f run_live.sh ; pkill -f "http.server 8776"
```

- **刷新只给两档（V1.7.0）**：`config.json` 的 `refresh.tiers` 为单一事实源——`active:120` / `calm:300`。  
  自动策略（`SPEED=auto`）：任一市场「常规交易(open)」→ 活跃档 120s（行情变化快）；盘前/盘后/休市 → 平稳档 300s（变化慢）。  
  两档都属「适中」量级，既不像 60s 以下那样有封禁风险，也不会因太慢显得卡顿；导播台时段图标题行右侧实时显示当前档位。
- **交易日判定 = 数据驱动，不用节假日表（V1.8.0 · 最重要的一条）**：  
  `markets.py` 读行情源自带的**报价时间戳**（A股 `sh000001[30:31]`、港股 `rt_hkHSI[17:18]`、美股 `gb_ixic[3]`）→ `session.all.<mkt>.traded_today` / `holiday`。  
  时钟只回答「这个钟点理论上该不该开」；**报价陈旧度才回答「今天到底开没开」**：  
  时钟说该开、报价却停在上一交易日 → 判 `closed` + `holiday=true`，并在页面把该市场压暗、状态写「休市」、悬停显示最后报价时刻。  
  实测（2026-10-06 国庆）：A股报价停在 `09-30 16:19` → 休市；港股 `10-06 11:21:42` → 交易中，`active=hk`。  
  **这套判定零年度维护，且能覆盖台风停市这类日历外休市**；比硬编码节假日表更硬。抓取失败时该市场不进 `asof` → 退回纯时钟判定，绝不因网络抖动误报休市。  
  ⚠️ 陈旧覆盖只作用于「常规交易(open)」段：盘前/盘后是否有 tick 取决于数据源，用新鲜度判会误杀。
- **A 股采集按交易日自动开合（V1.8.0）**：`COLLECT_CN=auto` 时，只有 `cn.traded_today==1` 才跑 `collect_live.py`，  
  并**强制平稳档**保护东财（东财「按频率不按 host 封」）。非交易日跑了也没数据，故自动跳过。
- **轮内顺序不可颠倒**：`collect_live.py` 会整份重写 snapshot（丢掉 markets/news/session），  
  必须跑在 `markets.py` **之前**，由 `markets.py` 在其上打补丁。「今天要不要采 A股」读的是上一轮写的 session（最多滞后一个间隔）。
- 想临时看指数更跟手：可 `SPEED=active` 或 `./run_live.sh 120`；想更省额度：`SPEED=calm` 或 `./run_live.sh 300`。
- 循环本身不产生新逻辑，只是把 ②③④ 串起来定时跑；**产物口径与单次构建完全一致**。
- **解说节奏只给两档（V1.8.0）**：解说席右上角「平稳 / 活跃」，默认跟随本轮刷新档位（活跃市→快播，休市→慢播）。  
  `speed` 同时决定每条流的登场间隔与打字速度。**这不是拉数据的频率**——拉数据频率由 `refresh.tiers` 决定，两者不要混为一谈。

## 5. 扩展方式

- **加解说人设**：新建 `personas/<key>.json`，写 `key/name/short/tag/desc/system/voice` 即可，引擎和页面不用改。`system` 是提示词，**只写气质特征、不写具体真人姓名**（合规红线）。
- **加市场**：在 `markets.py` 的 `MARKETS` 加一项（指数代码 + 交易时段），再在 `narrate.synth` 加该市场的专属段。时段判定走 `market_state()`，自动纳入轮值。
- **换 LLM**：`narrate.py --base/--model` 已参数化，任何 OpenAI 兼容接口都能用。V1.7.0 起支持预设：`--engine api --preset agnes`（从 `config.json` 的 `llm.presets.agnes` 读 base/model/key）；**已接通并实跑验证**：`base=https://apihub.agnes-ai.com/v1`、`model=agnes-2.5-flash`、认证 `Authorization: Bearer`、免费档 **10 RPM**（企业认证 20、Token Plan 1000）。
  - **频率保护（防封）**：`--rpm`（默认 10），人设间按 `60/rpm` 留间隔（10 RPM → 6s）；`llm_segments` 带重试（空响应/429/异常退避重试 3 次）——Agnes 免费网关**首调偶发 HTTP 200 + 空内容**，必须重试否则首个人设整段丢失。
  - **线上切换**：`run_live.sh` 默认 `ENGINE=local`（不烧额度）；`ENGINE=api ./run_live.sh` 即走 Agnes。api 引擎不出 `refs`（标的标签行），页面自动不渲染。
- **加数据源**：在 `collect_live.py` 加 source adapter，按「东财→腾讯→新浪」插入兜底链。**加源前先读《技术资源手册》§2.8 评估 IP 反爬风险。**
- **加音频（二期）**：`personas/*.json` 已预留 `voice.gender/rate/pitch`，接 edge-tts 时直接读。
- **升级真直播**：生成侧代码不需重写，只需换算力（生成仍在本地/常开机器，CF 只做分发）。


## 6. 关键纪律（都是实测踩出来的，别踩回去）

1. **页面每个数字都必须能溯源到真实源，不许出现人工构造值**（师傅 2026-10-05 原话「别自己编哈」）。曾犯的错：① 模拟「在线观众数」用成交额派生 → 已删（无可靠公开观众数源，东财人气榜接口返回「服务异常」）；② MVP 用自设加权公式算「综合评分」→ 已改为硬门槛池（成交额≥10亿 且 换手≥5% 取涨幅最高），页面只显示涨幅/成交额/换手三个真实字段。**宁可少一个指标，也不放编的数。**
2. **生成永远在本地，CF 只做分发。** CF Workers 免费版 Cron CPU 只有 10ms，把 LLM/TTS 塞进去必撞墙。
3. **东财限流是速率维度，不是 host 维度。** 15 个镜像 host 轮转只能缓解；压测式并发（100 请求）会把自己 IP 打进几分钟冷却。**采集要串行 + 限速。**
4. **带排序的全市场接口，逐页翻只能拿到榜单头部。** 东财 `fid=f3`、新浪 `sort=changepercent` 都一样——算涨跌家数会得出「800涨 0跌」。**算分布必须用无排序/按代码排序的分页**（东财 `fid=f12`、新浪省略 `sort`）。
5. **新浪 A 股指数有两种字段序，混用必出鬼数。** 长格式 `sh000001` = 名,开,昨,现,高,低；短格式 `s_sh000001` = 名,**现**,涨跌额,涨跌幅%。曾把短格式当长格式解析 → 走马灯显示「上证 -97.36%」。`parse_cn` / `parse_cn_short` 必须分开写。
6. **新浪行业板块 `newSinaHy.php` 的第 5 字段是加权平均价，不是涨跌幅。** 拿它算涨跌会得216% 这种鬼数。板块要用 `newFLJK.php?param=class`（概念板块），第 5 字段才是涨跌幅。
7. **成交量单位是「手」**（1手=100股）。新浪 `volume` 返回的是股，解析层已除 100。
8. **写日志的 `print` 一律 `flush=True`**，否则非TTY 下块缓冲会让日志"停滞"成假象。
9. **解说层不碰网络，采集层不写解说词。** 单向依赖，加数据源不会污染生成。
10. **资讯源必须「每源限量 + 交错轮转」**：CNBC 三个频道不限量会一口气占满 30 条，页面看起来像只有一个外媒。`collect_news(per_feed=2)` 交错后 CNBC/MarketWatch/NPR/SeekingAlpha 都能露脸。
11. **外媒 RSS 实测可用/不可用**（2026-10-05）：CNBC `search.cnbc.com/rs/search/combinedcms/view.xml?partnerId=wrss01&id=<频道>`、MarketWatch `feeds.content.dowjones.io/public/rss/mw_marketpulse`、`feeds.npr.org/1006/rss.xml`、SeekingAlpha `market_currents.xml` 均通且带原文链接；**Yahoo Finance 403 / Investing 403 / FT 502 / BBC 502 / SCMP 502 / Reuters 404 / SEC 403 / StockTwits 403**。
12. **港美股没有可靠的全市场排行源**（东财 clist 的 `fs` 不含外盘，新浪 vip 排行只有 A 股节点）。故港美股只做「指数 + 快讯」，涨跌家数/异动榜仅 A 股有——这是数据源的真实边界，页面已如实标注。
13. **写 snapshot 必须原子写**（`mkstemp` + `os.replace`）：曾因 `markets.py` 中途崩溃留下半截 JSON，`json.load` 直接报 line 1383 整条链路报废。三个写 snapshot 的脚本都已加。
14. **正则/脚本批量改代码后，语法通过 ≠ 正确**：曾用正则给三个脚本加原子写时，捕获组把路径变量吃空（`_os.replace(_tmp, )`），`ast.parse` 依然合法但运行必崩。**改完必须 grep 回验关键变量在位，并实跑一遍。**
15. **美股时段随夏令时变。** `MARKETS["us"]["tz_offset_h"]` 现为 -13（夏令时），11 月初回调后须改 -14，否则轮值会错一小时。

5. **长驻循环不能用 `nohup … & disown` 启动。**（2026-10-06）在受管 shell 环境下 `nohup` 启动的进程仍随会话收到 SIGHUP 被带走（日志里表现为 `Hangup: 1`、日志写到一半截断、进程消失）；`setsid` 在该环境不可用（`pgrep` 查不到）。**可靠做法：用工具的后台任务机制托管**（Bash 工具 `run_in_background=true`），或 `launchctl`。

14. **人设是资产，但人设里写死的市场名不是。**（2026-10-06）三人设 system 原文都写死「A股」（"播报一场**A股**比赛"/"今晚的题目是**A股**盘面"），港股/美股场次直接拿去用就与市场错位——与纪律 27 是同一类错误的 system 层版本。**改法：不改人设文件**（保持稳定），而是在注入时 `persona_system(p, F)` 把「A股」替换成目标市场，并追加【本场状态】（交易中=实时播报 / 非交易时段=复盘）。**状态行要对所有市场注入**——早先只在 `mk != "cn"` 分支追加，结果 A股 休市日反而没有状态行，而那正是最需要说清的场景。
15. **⚠️ prompt 禁令压不住口语化人设，必须有代码后处理。**（2026-10-06 实测）system 和 user 两处都写了「禁止自己换算星期/说成上周X」，retail/talk 人设（被要求"像真人说话、要有包袱"）仍顺嘴说出「昨天那场」「周一那天」（9/30 实际是周三）——**人设的"口语化"诉求与"日期准确"直接冲突，且人设优先于附加约束**。所以加 `_fix_relative_dates()` 后处理：休市场次把相对日期正则替换成绝对日期。**两个必踩的坑**：① 必须加**负向断言**——段落已含正确日期就整段不动，否则「2026年9月30日（周三）」会被啃成「2026年9月30日（2026年9月30日）」，把对的改成错的比不改更糟；② guard 正则**不能写 `%d年?%d月%d日`**（"年"变可选后 "2026" 后必须紧跟 "9"，匹配不到「9月30日（周三）」简写），须用 alternation `(?:%d年%d月%d日)|(?:%d月%d日)`。7 条用例单测全过。

17. **⚠️ 日期后处理别用正则套娃，会越改越坏。**（2026-10-06 实测，连踩四次）压「叠字日期」要处理 3 种写法（`2026年9月30日`/`9月30日`/`…30号`）× 2 个顺序 × 可叠 N 次。实测三次正则方案分别漏「日+号」反向、把三连叠压成「2026年2026年9月30日」、漏简写「9月30日9月30日」。**最终用扫 token 法**：正则只负责"找出全部日期 token"（这一步可靠），再按顺序保留第一个、逐个从原文切掉其余。10 条用例全过。

18. **新鲜度闸的基准时间要选对字段。**（2026-10-06 实测误杀）用 `snapshot.generated_at` 当基准会被**全杀**——它是 A股全市场采集时点，A股 休市时不更新，停在 10-05 19:08（17 小时前）。**必须用 `session.checked_at`**（markets.py 每轮刷新）。阈值也别定太紧：手动跑一次 `narrate.py` 而不重启循环时，行情停在上一轮、解说刚生成，差 20~40min 是正常的，10min 阈值会全误杀（实测 26min 被杀）。最终 `--max-age` 默认 **2700s=45min**，仍能拦住"循环挂了页面一直显示旧解说"（那会跨小时）。
19. **⚠️ 休市时不要回退到某个市场做"复盘"。**（2026-10-06 师傅明确要求 · V1.8.4）原逻辑 `active 不可用就回退 A股`（`else ("cn" if ...)`）→ 全场休市时生成一整套「A股收盘复盘」，内容是上一个交易日的数据 —— **既误导又易编造**（模型会为凑节奏去编家数）。师傅原话：「A股没开市不需要做什么复盘」「只针对开市中的市场解锁，午间休市可以解说你拿到的全球资讯」。改为三态：① `mk = active`（必须是 `state=="open"` 的那个）② `mk=None` → **全球资讯速览场**（只解读走马灯 + 外媒快讯，不碰任何单一市场）③ 不再有"A股休市复盘"模板。
20. **页面上的市场标签，数据源不属于该市场就必须隐藏，不能加"上一场"糊弄。**（2026-10-06 师傅明确要求）港股场次右侧「本场状况」顶着「A股 · 上一场 9月30日」—— 那一栏是 A 股涨跌家数/MVP/涨停池，与港股解说毫无关系，标出来纯误导。现在：非 A 股场次（或 A股 未开市）**整块面板 `display:none`**，不显示空态、不显示旧数据。同理 `bcMkt` 只显示当前解说真实对应的市场。
21. **prompt 里"禁止编造"要有可执行细则，泛泛说没用。**（2026-10-06 师傅原话：「严格按照快照信息来解读转化，不要添加」）任务段末尾固定追加【最高铁律 · 只解读，不添加】五条：① 只能用【真实数据】里出现的信息 ② **不许推断因果**（「因为…」「由于…」——数据只说涨了跌了没说为什么）③ **不许预测**（「明天会…」「后市看…」）④ 信息不够就说不够，别为凑段数注水 ⑤ 表达可花哨（人设的事），事实必须逐字对得上。**关键是"允许风格自由、禁止事实添加"要分开写** —— 一句笼统的"不许编造"会连人设的比喻一起压死。
22. **别让 prompt 自相矛盾。**（2026-10-06 实测）全球速览场里，走马灯含「上证指数 +0.31%」，而我同时写了"绝对不许报某个市场的指数点位" —— 自己打自己，模型只能二选一（实测倾向乱选）。**正确做法**：禁的是「编造」不是「引用快照数字」；走马灯数字是行情源当前报价、可以直接引用，只要求它说明这是「全球速览」而非假装某市场在盘中。**每次改完 prompt 逐条对一遍：有没有哪两条要求互相打架。**
23. **⚠️ 氛围设定会泄漏成字面内容，必须在 system + user 双侧显式封禁。**（2026-10-06 师傅实测抓出 · V1.8.5）人设写"模仿体育比赛的现场感"，LLM 就真的说出「**现在这球赛**，恒指涨了0.73%」—— 师傅：「我们是模仿体育比赛的氛围感，不是说球赛，说的东西还是市场的。」根因两层：① user prompt 里写了「像真球赛一样有起伏」把它往下带；② 人设给了「上半场结束」「这一球漂亮」这类**现成锚点**，模型直接搬进正文。**修法**：`build_prompt` 任务段顶部写死「这是**市场直播**，不是体育赛事直播」+ 列出禁词清单（这球/上半场/比分/球员/进球/开赛/战报/MVP），人设 system 里也放同款禁词。**规律：要什么风格就禁什么字面词** —— 想要"现场感"就得同时禁"球赛"，因为风格与字面在 LLM 那里不是一回事。
24. **人设先只留一个，跑通再扩。**（2026-10-06 师傅判断 · V1.8.5）师傅指出三个主播声线接近，且要求「先只有我一个（杨夏，散户嘴替），用我的文风，流程跑通了再新增」。原三人设（解说员·陈播/段云飞/赵小明）下线，历史备份已于 2026-10-08 清理时删除。新增人设 = 往 `personas/` 放一个 json + 在 `build_live.py` 的 `order` 数组加一个 key。**声纹真源是 skill `yangxia-writing-style`**（`references/style-manual.md` 有完整声纹规范 + `references/samples.md` 有真实范文片段），改人设先读它，不要凭印象编。
25. **⚠️ refs（正文末尾的标的标签）一直是 local 引擎独有的，AI 引擎恒为空。**（2026-10-06 师傅截图指出 · V1.8.6）`refs` 由本地合成器在拼句子时顺手挂上（它自己知道引用了谁）；`_parse_llm` 出来的段 `refs` 恒为 `[]`，页面 `if(!r.length) return ''` 直接跳过 → **标签完全不出现**。修法不是让 LLM 自己输出结构化 refs（那会新增编造面），而是 **`attach_refs()` 从 AI 已写出的正文里反向识别实体**，再回查快照拿真实涨跌幅与链接 —— 抽不到就不挂。**两条前置条件**：① `IDX_ALIAS` 口语别名表（「恒指」「英国富时」「巴西」→ 全称），AI 用简称而 `IDX_TICKER` 存全称，不映射就挂不上；② `IDX_TICKER` 必须与行情源实际返回的**准确名**一致（恒生国企指数行情源叫「国企指数」，不是「恒生国企」，缺这项会漏挂）。
26. **中文正文 vs 英文新闻标题：必须有对照表，否则永远匹配不上。**（2026-10-06 实测踩到）正文写「世行提醒人工智能资源集中」，快照标题是 `World Bank warns of AI concentration risks` —— 一个字符都对不上，`k in hay` 恒 False，标签挂不出来。故建 `NEWS_HINT_MAP`：**键=中文口语（从正文抽），值=英文关键词列表（去标题里找）**；资讯标签渲染成 `<a target="_blank">` 可点击打开原文。
    - **特异性纪律**：线索词越泛越容易误挂。「人工智能」「芯片」「俄」在财经新闻里篇篇出现（AI concentration / chip stocks / Russia 都是常客），挂上去会让读者点开发现"这跟我看的那条没关系"。**宁可少挂一个标签，也不能挂错。**
    - 打分用 `>` 不用 `>=`：同分时保留列表里靠前（更新鲜）那条，否则**最后**一条同分会覆盖掉它（实测「特朗普帮俄罗斯」被指到不相干的 MAGA 广告那条）。
27. **单人主播时不要用三列网格。**（2026-10-06 师傅指出 · V1.8.6）只有 1 位主播时 `repeat(3,1fr)` 右侧空两格，既浪费又把主播位撑高。改 `repeat(auto-fit,minmax(260px,1fr))` —— 卡片数变化时自动换行，**以后加主播不用改 CSS**。配套压缩：头像 38→32px、padding 14→10px、简介 2 行截断、ON AIR 徽标上移。（**V1.8.7 二次修正见第 50 条**：`auto-fit` 只解决了"格子数"，卡内仍是两行 + 徽标绝对定位，右侧照样空。）
28. **⚠️ 凡要求它「说某个时间/数字」，就必须把真值喂给它，否则它一定编。**（2026-10-06 实测踩到）全球速览场的模板让模型「说下一个交易时段什么时候开」，但 prompt 里**没有时段表** → 它只能猜，实测编出「A股港股下午两点半左右开盘」（A股 国庆休市、港股 16:00 已收，全错）。修法：把 `MARKET_SEGS` 的真实时段（A股 09:30-11:30/13:00-15:00、港股 09:30-12:00/13:00-16:00、美股 21:30-次日04:00）+ 各市场当前状态一起写进 prompt，并注明「只能照抄，不许自己算或猜」。**规律：prompt 里每一条"不许编"都要配上真值，只写禁令不给数据等于让它自由发挥。**
29. **⚠️「下一场是谁、几点」是道计算题，不能交给 LLM —— 给数据表也会被张冠李戴。**（2026-10-06 实测 · V1.8.7，是对第 48 条的补刀）第 48 条把**整张时段表**喂进 prompt，16:15 场（港股 16:00 已收、美股盘前、A股 假期休市）实测仍输出：「下一波要开盘的是港股，时间是 09:30-12:00 / 13:00-16:00。**A股也是这个时间开盘**，美股那是晚上 21:30 才开。」—— ① 把已收盘的港股说成"要开盘"（当晚真正先开的是美股 21:30）；② 把港股时段整段搬到 A股 头上（A股 实际 09:30-11:30 / 13:00-15:00）。**根因：表格是"陈述"，选谁是"推理"，模型做了推理且做错。** 修法三条：① 逐市场给**当前状态**（假期休市 / 今日已收盘 / 盘前，语义必须分开，都简化成「休市」会被它当成"等下就开"）；② `_next_open_fact()` 用 `session.all[*].segs` + `beijing_now` **算出**下一场开市（跳过假期市场、跳过 `s0<=0` 的前夜盘续接段、跳过落在周末的目标日），prompt 里明写「**已算好，照抄**」；③ 明令「除这一句外任何市场的开收盘时间你都不知道」，并在【最高铁律】加第 7 条（**时刻也是事实**，原先的禁令只管行情数字，管不住时段表）。**规律：凡是"从数据推一个结论"的动作，要么代码算，要么别在 prompt 里问。**  
    **⚠️ V1.8.8 推翻本修法**：师傅指出 prompt 里根本不需要让 AI 判断下一场——连"算好照抄"都是多余的议题（本质还是让 AI 主动提起、排时间表）。V1.8.8 起 `_next_open_fact()` 已删除、"下一场开市"整段从 prompt 移除，AI 只解读系统已选定的本场市场与已给数据，不再展望下一个开盘（见第 57 条）。
30. **单人主播位：ON AIR 必须跟在姓名后面，简介同行。**（2026-10-06 师傅指出 · V1.8.7）师傅原话：「ON AIR 应该放在姓名后面，介绍不用单起一行，跟着后面就可以，不然右边一大块空白」。原写法 `position:absolute;right:12px` 把徽标钉在卡片右上、简介另起一行 → 姓名到徽标之间空出一大块，卡片还是两行高。改为**单行 flex**：`头像 → 姓名 → ON AIR → 角色·简介`（简介 `flex:0 1 auto;min-width:0` + `nowrap + ellipsis`）。**规律：卡片内的"角标"用绝对定位 = 用空白换对齐，人少时一定难看；能进流就别浮起来。**
31. **标签行要与正文同列，不能靠 `flex-wrap` 自己退行。**（2026-10-06 师傅指出 · V1.8.7）师傅原话：「后缀标签没有跟正文左对齐，跑到跟时间对齐了」。根因：`.seg` 是 `display:flex;flex-wrap:wrap`，标签行写 `flex:1 1 100%` → 换行后从**容器最左**（= 与「时间」同行首）起排。改为**两列 grid**（`grid-template-columns:auto minmax(0,1fr)`）：时间钉第 1 列，正文与标签行同占第 2 列，天然左对齐、时间列宽随内容自适应。**规律：只要出现"左边一列标签 + 右边一块内容"的多行结构，直接用 grid，别用 flex-wrap 硬凑。**
32. **页面上的裸读数要能一句话说清是什么，否则删掉。**（2026-10-06 师傅提问 · V1.8.7）师傅问「00:40 这个信息是什么用的，可以去掉」—— 那是 `#bcClock`，显示当前播出段在**场次时间轴上的偏移秒数**（`t=40` → 「00:40」）。它既不是真实时刻（真实时刻在每段正文左侧），又与「本场时间轴」这个内部概念绑定，对观众是纯噪声。已连同 `fmtClock()` 与 markup 一起删除。**规律：`t`（场次相对秒）只用于播放调度，永远不要当内容展示给观众 —— 观众看到的每个时间都应该是真实北京时间。**
33. **"没有基准的对比"和"币种换算"是两条被漏掉的编造通道。**（2026-10-06 实测 · V1.8.7）禁用数字的规则原先只管「上面没写的数字」，实测漏掉两类：① 对比——新闻标题只有 `upsizes ... to up to $8.35M`（一个数），模型写成「融资**扩到** 835 万美元，**扩了一倍多**」（原额度快照里没有，倍数纯属虚构）；② 币种——同一句还冒出「**大概六千万人民币上下**」（汇率它不知道）。修法：第 1 条补「没有基准的对比 = 编造（「比上个月」「较昨日」同理）」、第 6 条补「不许做币种换算，美元只说美元」。**规律：禁令要按"算子"枚举，不能只按"数据项"枚举** —— 数字 ×(对比/换算/约算/截断) 每一种都是一个入口。
34. **⚠️ 只给行情不给日期，口语人设就会把"刚刚发生的"讲成"昨天"。**（2026-10-06 实测 · V1.8.7）全球速览场的 prompt 里**一句日期都没有**（日期只在 `mk=="cn"` 的复盘分支注入），实测模型把当天 15:59 的港股收盘价说成「最后报价停在**昨天**的下午三点五十九分」、把当天涨跌说成「昨天」。修法：`build_prompt` 顶部对所有场次统一注入【今天是】+ 本轮快照采集时刻，并写明「禁止说成昨天」。**规律：日期是事实的锚，任何"解读型" prompt 都要有，不能因为它属于"上下文"就省掉。**
35. **⚠️ 全球速览的走马灯里混着 A 股指数，A股 休市日那是上一个交易日的旧数。**（2026-10-06 实测 · V1.8.7）`global_ticker` 无市场字段，A股 国庆休市时它仍带着 **9/30 的上证 +0.31%**，而这一栏在页面/prompt 里叫「全球市场**实时涨跌**」—— 拿旧数当今天播。修法：mk=None 时只有 `cn.traded_today` 为真才保留 A 股指数，否则过滤掉，并在 prompt 里显式写「A股 指数不在这里 = 不许点评 A股 点位」。**规律：跨市场拼盘列表必须带"数据日期"维度，否则休市市场会冒充实时。**
36. **段数不足（<6 段）也要重试。**（2026-10-06 实测 · V1.8.7）同一 prompt 在 `temperature=0.9` 下实测出过 5 段（要求 6~10 段）—— 事实全对但场次太薄。`llm_segments()` 里加了「解析后段数 < 6 → 抛错重试」，与截断重试共用同一套退避。**规律：LLM 的"质量缺口"要拆成可检测的指标（截断 / 段数 / 空响应），每种一个判据，别指望一句"写多点"能稳定生效。**
37. **⚠️ 职责边界铁律：代码负责确定性，AI 负责扩散性。**（2026-10-06 师傅点名 · V1.8.8）师傅原话：「提示词里根本不需要让 AI 判断下一场，就是当前获取到什么市场的行情就解说什么行情。代码与 AI 各自的作用职责要分清，谁负责确定性、谁负责扩散性。」**落地**：① 选哪个市场（`mk`）、各市场状态（`session`）、新鲜度（`checked_at`）、可用数据范围——全是代码算好的**确定性**，AI 不碰；② AI 只拿"系统已选定的本场市场 + 已给出的数据"做口语化**扩散**（翻译数字、说感受、聊消息面）；③ 凡系统没给 AI 的信息（含下一市场的开收盘时间、任何时段表），对 AI 而言就是不存在，**禁止 AI 自行判断 / 展望 / 预告**——实测即使用"算好照抄"的写法，模型仍会顺嘴补「美股今晚21:30开，到时候再看看吧」，必须在铁律第 7 条把「XX今晚X点开」「等X开盘再看」这类具体形态也点名禁掉；④ 若将来要在页面展示"下一个开盘"，那是代码/页面层的事，**绝不在 AI 解说词里**。
38. **⚠️ 兜底源只补缺，不许污染确定性判据。**（2026-10-06 · V1.8.9）美股加兜底源（Nasdaq API /腾讯 `us*`）后，`asof` 会把兜底条的**昨日收盘时间**一起取max → 休市/盘中的"今天开没开市"判决可能被兜底时间带偏（腾讯 `us*` 停在 10-05 16:48，Nasdaq 只有日期无时分）。修法：`asof` 只采信 `src=="sina"` 的条目，兜底源缺失时 `asof=None` 退回纯时钟。**规律：兜底源的价值是"主源挂时不瞎"，不是"口径更优"；凡是喂给确定性判据（时段判定、新鲜度闸、交易日判定）的字段，必须只认主源。** 同时兜底**只补缺项**、绝不覆盖主源（新浪的 asof 精确到分，兜底没有）。
39. **⚠️ HTTP 200 ≠ 活源。死源会静默吃掉请求位。**（2026-10-06 实测 · V1.8.9）`MarketWatch「市场脉搏」= mw_marketpulse` 返回 200、字节数正常，但 **pubDate 全是 2025 年**（最新 2025-07-03）→ 被 24h 过滤全丢，快照里命中 0，白占一个请求位。同机构 `mw_topstories` 是活的。**规律：RSS/接口源必须校验"最新一条的时间戳"，不能只看状态码**；建议每次新增源都先 `curl` 打印前 3 条 pubDate 验活，别凭"200 看着正常"就上架。同类实测不可用清单见 `markets.py` FOREIGN_FEEDS 上方注释（Yahoo 403 / Stooq 404 / Google 全站 000 /东财美股不稳）。
40. **⚠️ 滚动覆盖靠"跨轮累积"，不靠加频率。**（2026-10-06 师傅提问 · V1.8.9）师傅问"全球资讯是不是该 20 分钟拉一批"，方向对但根因不是频率：改之前 `snap["news"] = news` **每轮整份覆盖** + `per_feed=2`（7 源= 14 条上限），页面只剩**最近约 15 分钟**的快讯，稍早内容全被冲掉 → 盘前/休市几乎没素材。修法：`.cache/news_history.json` 存30h 池，每轮把新拉条目**按 link/标题去重合并**、倒排、过期剔除、cap 120。实测 9 → 20 条，二次跑「本轮新增 0」（去重生效、池不冲不重）。**规律：RSS 是"最新 N 条"语义，轮询必然反复命中同一批头几条 → 每源永远只能露per_feed 条脸；"全天候有素材"要靠累积池，加频率只是重复请求。** 拉取节奏与轮询节奏后续要解耦（RSS 分钟级更新、循环 120s/300s 轮询属浪费），但那是优化项，不影响正确性。
41. **⚠️「外媒渠道取行情」这条路走不通，别再试。**（2026-10-06 师傅给出 GitHub google-finance topic 页 · V1.8.9 复测）师傅建议参考 `github.com/topics/google-finance`，实测结论：那批仓库（ravc / GoogleFinanceAPI / google-stock-realtime / finance / BaseNodeRoutes…）**全是 cheerio / playwright 抓 HTML 或 Google Sheets 公式**，没有一个是公开 API，**共同前提是能直连 google.com**；而本机 `www.google.com` 与 `www.google.com/finance/quote/.INX:INDEXSP` 均 **HTTP 000 超时** → 这类方案一律不可用。同批实测：Yahoo Finance v8/v7 **403**（sad-panda 反爬）、Stooq **404**、Google News RSS **000**、东财美股 `100.DJIA` 首次成功后连打 3 次全 **000**（且东财限流按 host 计，卧龙台多项目共用）。**可用**：Nasdaq 官方 API `api.nasdaq.com/api/quote/COMP/info?assetclass=index`（连打 3 次稳定，**但只有 COMP 通**，INDU/SPX/DJI/SP500/OEX 全部 `data:null`）、腾讯 `qt.gtimg.cn/q=usDJI,usIXIC,usINX`（一次批量拿全，字段序 1名 2代码 3现价 4昨收 5今开 30时间 31涨跌额 32涨跌幅 33高 34低 37成交额万）。**规律：财经源选择前先 curl 验活并问"它给的是结构化报价还是标题文本"——后者要从文本里正则抠涨跌幅，等于新造一个编造面，直接违反纪律 57。**
42. **⚠️ 同一个供应商，Cloudflare 可能只封某一条出口路径——先查出口 IP，再怪源。**（2026-10-06 师傅提供 API key 仍 403 · V1.9.0）eulerpool 直连返回 **403 "Sorry, you have been blocked"**（**硬拉黑，不是 JS 挑战**，`cf-ray: ...-SEA`），换浏览器 UA / HTTP2 / Cookie jar / 装官方 SDK 换 httpx（TLS 指纹不同）**全部无效** → 说明是 **IP 级封禁**。定位法：查 `env | grep -i proxy` 发现 WorkBuddy 默认走 `127.0.0.1:50416`，再扫常见本地代理端口（`nc -z 127.0.0.1 7890/7897/1087/8888…`）找到 `7897` —— **走它就200**（同代理下 google.com 也 302 可达）。**规律：403 先分三段查——① 是挑战页还是硬拉黑（`Sorry, you have been blocked` vs `Enable JavaScript`）② 直连试完再试换 TLS 栈（httpx/requests）③ 最后才是换出口 IP；本机代理是最后的杀手锏。** 教训要记住：WorkBuddy 默认代理的出口 IP 可能已被某些站拉黑，新增外部源时**必须显式指定 `proxy` 配置项**，不能依赖环境默认。
43. **⚠️ 拿不到数值的数据源，必须在prompt 里点死"不许报数字"。**（2026-10-06 · V1.9.0）eulerpool `calendar/economic-calendar`（及其 `/history` 版本，后者**忽略 release_id 参数**）只给 `release_name/release_date/notes`，**没有 actual/prev**；ForexFactory 周历也只有 impact 等级。但模型面对「FOMC Press Release」这类条目极易顺口编「市场预期降息 25 个基点」——**这是最难自察的编造，因为听起来太合理**。修法：铁律新增第 8 条「经济数据只说事件、不报任何数字」，并在日历渲染行再次点明「只有事件名和日期，任何数值都没有」。**规律：禁令要按"数据类别 × 推导路径"枚举，光写"不许编造"盖不住"日程表→预期值"这种看起来很合理的推导。**
44. **⚠️ 多源混合时，快讯选取必须以时间为第一序，不能按插入顺序。**（2026-10-06 实测 · V1.9.0）eulerpool 是"逐个 ticker 插入"到快讯池的，若直接取前 8 条，会变成**配置表里最后一个 ticker 的旧新闻霸占全部名额**（实测先出 GOOGL/META 的隔夜旧闻）。修法：`facts()` 里先按 `time` 字段倒序排序，再做"eulerpool 优先 + 其余补齐"。**规律：任何"合并多源 + 取前 N"的逻辑，排序键必须是数据自带的真实字段，绝不能让上游的采集顺序泄漏进选择结果。** 另外 eulerpool 个性内容（挂 ticker + 具体数字）比通用 RSS 的宏观长文更适合解说，故同类里优先用。
45. **⚠️ 新增外部源一律做成"优雅降级"，且凭据只走环境变量。**（2026-10-06 · V1.9.0）`eulerpool_src.py` 定位为**增量源不是主源**：key 未设 / 代理端口不通 / API 挂 → 只打日志并跳过，快讯池照旧用 RSS 出内容，**绝不因新源把整页拖挂**（实测两种失败场景均干净退出，原因可读）。API key 只从 `EULERPOOL_API_KEY` 读，**不入库、不打日志**（config.json 里只存 `api_key_env` 变量名）。已验证能力边界：美股个股新闻可用、**港股 7 种代码写法全空**、全市场 `news/feed` 线上 404。
46. **⚠️ 确定性数字必须代码兜一遍，不能只靠 prompt 声明。**（2026-10-06 实测抓到的"转写变形" · V1.9.0）prompt 里明明白白写着「恒生科技 **+0.94%**」，模型输出成「**1.94%**」。**注意这跟"凭空编造"不是一回事** —— 凭空编造（新数字凭空冒出来）prompt 禁令能拦；但**转写变形**（把已有数字写错，数字看着合理、禁令里也没写"不许算术错误"）模型会自己滑过去。修法：`_fix_market_pct()` 在写盘前把正文里每个百分比与行情真值集合对一遍。三条设计约束缺一不可：① **必须同段有指数名锚点**才认作行情百分比 —— 否则快讯里公司自己的数字会被误改（实测 NVIDIA 净利率 55.6% 若被当成行情改掉，那才是真事故）；② 对不上的**直接删数字**不猜哪个对（宁可留「涨了不少」也不留错数字）；③ 删除用占位符再统一清标点，否则会留下「涨到，。」（实测踩到）。**规律：prompt 禁令的覆盖面是"语义编造"，覆盖不了"转写/算术"这类低层错误；凡是纪律 57 定义的确定性量，代码必须自己验一遍。**
47. **⚠️ prompt 里通篇用 `**加粗**` 会让模型把星号带进正文。**（2026-10-06 实测 · V1.9.0）我方 prompt 为强调重点大量使用 `**…**`，模型学完后**连解说正文也吐星号** —— 实测输出「…835万美元，*（这句我不懂矿，别较真）*」。修法：铁律里点死「正文里绝对不许出现任何 markdown 符号（`*` `**` `#` `` ` `` `-`）」。**规律：prompt 的排版风格会被模型当作输出风格示范；强调重点改用「⚠️ 硬禁令」措辞而不是加粗。**
48. **⚠️ 解说口吻里最致命的是"元叙述"——模型跳出来跟观众解释自己。**（2026-10-06 实测 · V1.9.0）碰到不熟悉的标的，模型会写「这句我不懂矿，别较真」「这个我不确定」——**直播里等于解说员当场承认自己刚报的数不可信**。修法：铁律点死具体形态（不懂/别较真/记不清/我不确定），并给替代做法：「遇到不熟悉的标的，只说它客观上发生了什么，不许承认自己不懂」。**规律：新增数据源（尤其个股级）必然带来"模型不熟悉的标的"，元叙述禁令要与数据源同步上线，否则第一次跑就会出现。**
49. **⚠️ 后台跑长任务：`export` + `nohup ... &` 组合会静默失败。**（2026-10-06 连续踩坑 · V1.9.0）`export KEY=... && nohup cmd &` 放到后台时，**环境变量在子 shell 里没生效**、且进程被立刻回收 → 表现为「任务 4 秒完成、log 只有两行、输出文件时间戳没变」，误判为"prompt 有问题"，白排查一轮。可靠做法：**前台直接跑**（`narrate.py` 约 40~90s，可接受），或 `nohup cmd > log 2>&1 & disown`（**macOS 无 `setsid`**，别照抄 Linux 写法）。**规律：判断任务是否真跑过，看输出文件 mtime 与 log 尾部，不要只看"任务 completed"。**
50. **⚠️⚠️「禁提 X」和「不提供 X」是两种完全不同的实现——要真正闭嘴就得不给数据。**（2026-10-06 师傅指出的真 bug · V1.9.1）师傅原话：「你当前是美股盘前就只讲美股的东西，为何要提 AH 无关的」。**两层根因都在代码里**：① `mk` 判定只认 `state=="open"`，**盘前（pre）被判成"没开市"** → mk=None → 退化成全球速览场；② prompt 里"以下市场当前没有实况，不要报它们的指数点位"这段，**名义上禁了数字、实际上把「A股休市／港股已收盘」两个状态送进了上下文**，模型照读就成了开头三句。修法：盘前（`pre`）也算"本场聚焦市场"（**但 `post` 不算**——盘后属"今天已收工"，讲它是复盘，与「A股没开市不做复盘」冲突）；别家状态**整条不出现**，不是"出现但禁提"。**规律：模型手里有什么就讲什么；"禁提"只是提示，"不给"才是闭嘴。同理适用于"外围市场"数据块——我第一版以为外围该留别国指数，结果港股恒生仍被当"外围"念出来（实测第 4 段），最后是整条删除才解决。**
51. **⚠️ 财务指标口径会"数字对、指标名错"，且对账查不出来。**（2026-10-06 实测 · V1.9.1）源文 `Nvidia's 55.6% **net margin** and $96.7B free cash flow` 被解说成「英伟达**毛利**率 55.6%」—— **数字分毫不差，指标名换了**。这比数字错更隐蔽（按数字对账查不出来），且**事实相反**：毛利率远高于净利率，说成毛利率等于把成本结构讲宽松了。根因：中文里 margin 只能译"利润率"，模型在"净/毛"之间随手挑。修法：`facts()` 缓存源文本（`F_NEWS_CACHE`）→ `_fix_metric_name()` 比对源里的英文口径，正文写错就替换（只认 net/gross/operating/profit margin 这一组高频混淆项，**不泛化猜测**）。**规律：凡是"数字 + 指标名"成对出现的确定性事实，两个维度都要校** —— 数字对不代表事实对。
52. **⚠️ 行情源精度 ≠ 解说精度。**（2026-10-06 实测 · V1.9.1）指数点位源给的是 `51267.8984`（4 位小数），模型照搬念出「五万一千二百六十七点八九」（自己都嫌离谱地加了句"这个数字精确得离谱"）。修法：prompt 渲染时一律 `%.2f`，并明写「点位已四舍五入到两位小数，照这个念，不要念源里的更多小数位」。**规律：数值要按"用途"决定精度——报价格 2 位、报涨跌幅 2 位、报百分比变化 1~2 位；把原始精度直接给模型 = 让它替我们做格式化决策。**
53. **⚠️ 数据少 → 模型转向"预测 + 免责声明"组合，必须成段兜底。**（2026-10-06 实测 · V1.9.1）盘前场次按纪律禁掉外围与别家后只剩「3 指数 + 几条快讯」，模型"没料可讲"就转向两个坏习惯，且**互相掩护**：第 9 段「今天要是真开了，科技股那边估计还得热闹」（预测，踩铁律 3）+ 第 10 段「（这句不负责任，别较真）*」（元叙述+ markdown）。只禁文字容易漏。修法：`_strip_junk_segs()` **成段处理** —— 剥掉 markdown 与括号注释后若实质内容不足 8 字= 整段丢；含免责词则剥离，剩不下内容也丢；命中预测句式（要是真开/估计还/我猜/明天会…）整段丢。**规律：禁令约束"句子"，数据稀缺引发的坏习惯会升级为"整段"；且违规往往成对出现（预测+免责连着来），要按段而非按句检测。**
54. **⚠️ Python 字符串里别嵌中文双引号。**（2026-10-06 实测 · V1.9.1）写 `"（不是"禁提"而是"没给"）"` → 中文引号 `"` `"` 被当作字符串边界，`py_compile` 直接 SyntaxError（报错位置还指在字符串起始处，看不出真因）。中文内容里要强调就换单引号或破折号。**附：同一轮也踩了"改完不回验就下结论"——过滤代码自己写错方向（按"本场市场指数名"建黑名单，港股恒生根本不在里面，一个都没滤掉），跑一次解说才发现没生效。以后写过滤逻辑，务必用真实数据单测一遍再进主流程。**
55. **⚠️⚠️ 凡报数字必须带时点，否则"陈旧数据"会被播成"实时"。**（2026-10-06 师傅截图指出· V1.9.2）师傅批「还没开盘，道琼斯这个涨幅哪条资讯来的，乱说了啊」。**注意这不是编造** —— `+0.18%` 确实来自行情源（`src=sina`），但 `asof= 北京 10-06 04:49 = 美东 10-05 16:49` = **上一交易日收盘**；当时是周一 21:26、美股 21:30 才开盘 → **盘前拿到的本就是上一交易日收盘价**，而 prompt 只写「+0.18%」不带时点，模型就播成「**现在**…**涨了**0.18%」。**规律：数字对 ≠ 事实对**（与纪律 71「指标名错」同源）—— **确定性事实有两个维度：值与时点，两个都要进prompt 都要校。** 修法三层：① 盘前**一律不给涨跌幅**、只给点位 + 「（上一交易日收盘价，本场还没开盘，没有今早的涨跌）该报价距今 N 小时」；② **日期行按场次分叉** —— 盘前要反过来说「不许说成今天涨了」，因为原line「禁止说成昨天」（V1.8.7 为治"把今天收盘说成昨天"）在盘前会**逼模型把收盘价说成今天的**，比说昨天更坏；③ 词面兜底 `_fix_stale_quote()`。
56. **⚠️ 兜底改写比原句更危险时，宁可删。**（2026-10-06 连踩两次 · V1.9.2）`_fix_stale_quote()` 前两版都错、都是实测才发现：v1 用正则邻接 `(时间词)[^，。]{0,10}(涨跌)` —— 师傅原句「道琼斯**现在** 51267.90 点，**涨了** 0.18%」中间隔 11 字，**没被改到**；v2 改写成「上一交易日收在」——把「今天涨了 1.05%」改成「上一交易日**收在了** 1.05%」，**病句**（涨跌幅是相对昨收的量，不能说"收在"）。v3 正解：**不邻接、不改写，整句丢** —— 按中文句读切分，同句内出现「时间词 ∩ 涨跌词」即丢。实测 5 段入/4 段出，盘中场景完全不动。**规律：① 长距离共现必须按"分句/分块"判定，正则邻接必漏；② 后处理优先"删除"而非"改写"，改写要重新造句（容易造出病句），删除不会。**
57. **⚠️ 人设里的每个示例都会被模型当模板照抄——示例违规等于铁律形同虚设。**（2026-10-06 实测 · V1.9.2）`personas/yx.json` 的「括号碎碎念」项，示例写的是 `*（这句不负责任，别较真）*` ——它**同时违反** markdown 禁令（人设第 5 条）与元叙述禁令（纪律 68）。这才是"别较真 + 星号"反复出现的**真正根源**：不是禁令写得不够，是模型一直学的是这个坏示例。已换成合规口语版「（这行数我看了三遍才敢念）」，并加一句「碎碎念是**你对读者说的话**，不是替自己免责声明」。**规律：写人设时，每个示例要与铁律逐条对齐；示例是模型最容易学的"格式模板"，禁令只是"说明"。**
58. **⚠️ prompt 内部自相矛盾会让模型两头堵，要逐句自查。**（2026-10-06 导出自查时抓到 3 处 · V1.9.2）① 定性句`subj="美股（开市场中）"` 在盘前是错的（state=pre）→ 模型第一句定性前提就错；② 「⚠️ A股今日没有交易…」在单市场场次仍出现 → 又把 A股 送进上下文（纪律 70 同理，已改为只在 `mk is None` 时给）；③ 「禁止说成昨天」与盘前数据自相矛盾（见纪律 75②）。**规律：改prompt 后必须把全文导出**逐段读一遍，特别看三类句子——**定性句、日期/时点句、跨市场提示句**，它们最容易与新逻辑打架。工程做法见 `evidence/prompt_v192.txt`（每轮把 system+user 全文落盘，可直接 diff 两版差异）。
59. **⚠️ 时间戳精度不统一会让时点判定静默失效。**（2026-10-06 实测 · V1.9.2）`session.checked_at` 是 `'2026-10-06 18:59'`（**16 字符，只到分钟**），而代码按 `"%Y-%m-%d %H:%M:%S"` 解析 → 抛异常被`except` 吞掉 → `_age_min` 恒为 None → "陈旧报价"提示永不触发（我以为改好了，实际没生效）。修法：**解析要兼容多格式**（带秒/不带秒），失败时退回 `session.beijing_now`（带秒），且**判定失效要能被发现**（写单测断言"陈旧场景必须打出提示"）。**规律：所有时间字段的精度/格式要统一假设；静默吞掉的解析异常是时点逻辑的头号杀手。**

60. **⚠️⚠️ 改了 `markets.py` 必须重启观看服务，否则页面永远显示旧时段。**（2026-10-09 真踩 · V1.9.26/1.9.27）A股盘前段（08:00-09:30）加好后，页面 09:05 仍显示「全场休息」，我一度以为逻辑没生效。**根因不是逻辑，是进程**：`serve_live.py` 是常驻进程，启动时就把 `markets` 模块加载进内存，Python 的模块缓存让 `/__session__.json` 一直吐旧口径；而页面恰恰是每 4s 拉这个端点、**用旧值覆盖掉刚构建的新页面**（`live.html` 里烙的其实已经是「A股 · 盘前」）。修法：`python3 start_server.py restart`。**判据：改完看 `/__session__.json` 的输出，而不是只看 live.html 里的 baked session——两者来源不同（前者现算、后者是 `snapshot.session`，由上一轮 markets.py 写入）。** 对照：`live.html`/`build_live.py` 的改动**不需要**重启（循环每轮起新子进程）；`snapshot.session` 里的字段要等下一轮采集（≤300s）才更新，所以新加字段在前端必须**容错回退**。
61. **⚠️⚠️「三市场全 closed」≠「一整天结束」，别一律写「全场休息」。**（2026-10-09 师傅指出 · V1.9.27）师傅原话：「导播台里就有交易时段分布，我觉得我们应该整理一下这个时段显示的全表，全天24小时怎么划定状态」。**做法：不靠记忆、逐分钟扫全天**（1440 个分钟点求 owner，脚本见 `docs/时段状态总表.md` §7），把「谁在播、什么状态」的边界全部实测出来。结论：常态工作日**只剩两个真空档** —— 12:00-13:00（A股 11:30 收、港股 12:00 收，13:00 双双续盘）= 午休；冬令时 16:00-17:00（港股已收、美股盘前 17:00 才开）= 场次交接。已新增 `IDLE_WINDOWS` 给空档命名（`idle_name`/`idle_note`），**active 仍为 None、不发节目**，narrate 选场逻辑（只看 `active`）零改动。**同一轮扫描还抓到一个冬令时硬 bug**：美股常规段被 dst 平移到 1350-1500 后，旧归一化 `if m2 < aa-1440: m2 += 1440` 在 `m=0` 时阈值 `-90` 不触发 → **冬令时 00:00-01:00 明明在交易中却被判休市**（11 月一到就会露），已改成 `m / m+1440 / m-1440` 三向比较。**规律：跨天时间段 + 任何平移（时区/dst/单位换算）必须用「多周期比较」而不是「单侧补偿」；时段这种"一天一圈"的规则，改动后一律用逐分钟全扫回归，不要抽查几个点。**

62. **⚠️⚠️ 周末（周六/周日）A股/港股必须强制 `closed + holiday`，且独立覆盖、不可被工作日守卫短路。**（2026-10-09 真踩 · V1.9.28）旧写法把周末判定挂在 `if ... and not is_weekend and code=="open"` 上 → `not is_weekend` 在周末恒为 False，直接把整条 holiday 覆盖短路掉；结果周六/周日 10:00 被 `_state_of` 的时钟段（09:30-15:00）判成「A股/港股 交易中」，时段图错误点亮，与「周末全休」矛盾。**修法：周末对 `cn/hk` 单独 `if is_weekend and k in ("cn","hk")` 强制 `closed+holiday`，独立于 asof（a 为 None 也要压）。⚠️ 注意美股不在此列**——其常规段 21:30-次日04:00 跨到北京周六 00:00-04:00 本就是真实盘中（美东周五常规段），须保留时钟判定，否则会把真实在播的美股误压成休市。空档命名在周末补「周末休市」（非午休/交接空档时显示）。**规律：凡「某类日期要特殊压制」的逻辑，写出来要直接命中该类（正向 `if 周末 and 市场∈{cn,hk}`），不要用「非周末才处理」的负向守卫去包裹——负向守卫一旦遇上该类就整条失效，且静默不报错。** 复验：20 条单测覆盖「周末 cn/hk 强制休市 / 周六凌晨美股仍 open / 工作日节假日仍覆盖 / 正常日不受影响 / fresh 无 asof 也能压」。

63. **⚠️⚠️「本轮残缺」绝不能覆盖「上一轮完整」——日内分时的同日回退。**（2026-10-09 师傅截图 · V1.9.29）师傅截图：「统计台的日内走势数据为 N/A」。**根因不是接口坏**：实测腾讯分时在**开盘前几分钟**只回 1–2 个点（09:21 轮 1 点、09:28 轮 2 点，同一时刻接口本身正常、09:34 已回 8 点），而 `collect_intraday` 的守卫是 `len(pts) < 3` 直接判失败；更要命的是 `markets.py` 里 `if intra: snap["intraday"] = intra` 是**整体替换** —— 本轮 `{"us":…}` 把上一轮三个市场一起顶掉（`collect_live.py` 的「继承上一轮字段」只继承**本轮完全没有的键**，`intraday` 有值就轮不到它兜底）。于是 A股/港股整段 N/A，且要等下一轮（最长 300s）才可能恢复 —— **开盘那几分钟恰好是直播最热闹的时候**。两层修法：① **门槛 3 → 1**（有多少画多少，1 点也出图）；② **同日回退** —— 本轮点数**少于**上一轮同市场、且两者 `date` **相同**时，沿用上一轮那份更完整的；**跨交易日不沿用**（宁可 N/A 也不显示错日期的图，因为图下说明文字写的就是日期）。13 条单测覆盖（盘前 1/2 点出图、0 点+同日沿用、同日抽风沿用、跨交易日不沿用、0 点无上一轮才失败、多市场独立）。**规律：任何"本轮采集结果整体替换上一轮"的字段，都要问一句「本轮残缺时谁来兜底」—— 上游的"继承上一轮"只覆盖**缺失**的键，覆盖不了**残缺**的值；单调递增的日内指标用「同日取更完整者」既简单又不引入前视。**

- 人设一律「气质风格标签」，`personas/*.json` 的 `system` 里不出现任何具体真人姓名。
