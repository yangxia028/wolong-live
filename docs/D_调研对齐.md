### 1.3 接入 narrate 的方案（**待师傅确认是否启用**）

抓取器已产出 JSON。若要进解说，改动很小（与 A/B/C 同源通道），方案如下，但**默认先不接**——师傅说"辅助分析盘面即可"，即它是背景而非主线：

```
narrate.facts()：
  rrg = json.load("data/rrg_state.json")（读不到则 rrg_summary=None）

narrate.build_prompt()：

  → 铁律：只作背景、必须带"数据截止日"、不当预测（"后10日↑概率"是回测统计，不许讲成"接下来会涨"）
```

⚠️ **三条定位纪律**：
1. **跨资产格局背景 ≠ A 股行业主线** —— RRG 不含 A 股行业，解释不了「今日半导体为什么领跌」；价值是给解说一层"全球资金往哪类资产去"的背景。
2. **必须标注数据截止日**（日频数据不许说成"现在/今天"）。
3. **不当预测播** —— 页面的"后10日↑概率/方向参考"是回测统计，只作背景提示。

## 2. 维度二：推特 / X 抓取（**三渠道评估完成**）

### 2.1 评估对象

师傅给了三个候选：`twitterapi.io`、`tweetapi.com`、`d60/twikit`（外加 v2 已降级备选的 `xiaoxiunique/x-kit`）。

### 2.2 三渠道对比（7 维度）

| 维度 | **twitterapi.io** ✅推荐 | tweetapi.com | d60/twikit |
|---|---|---|---|
| 类型 | 付费第三方 API（REST） | 付费 API 类（中文文档，疑似同类） | 免费 Python 库（模拟登录） |
| 鉴权 | **单 `X-API-Key` header** | 待补（疑似 API key） | **需真实 X 账号 cookie/账密** |
| 云端可达 | ✅ 纯 HTTPS + key | 疑似 ✅（待补） | ⚠️ 需维护账号 session，**cookie 上云会过期** |
| 按用户名抓 | ✅ `GET /twitter/user/last_tweets?userName=<handle>` 返回 JSON | 待补 | ✅ `get_user_tweets`（但需先登录） |
| 成本 | **$0.15 / 1000 tweets**；**免费额度 $0.1（免信用卡）**；无月费 | 待补 | **$0（但隐性运维成本极高）** |
| 限流 | 1000+ RPS，~700ms | 待补 | 无官方限流，**X 反爬可能封号** |
| 合规 | 第三方 SaaS（灰区但成熟，1000B+ 调用） | 待补 | **违反 X ToS** |
| 接入代码量 | **极低**（1 个 requests.get + header） | 待补 | 中（登录态管理 + 反爬规避） |

### 2.3 结论：哪个接入成本最低最方便

> **推荐 `twitterapi.io` 作为主选。**

- **"接入成本最低最方便"指综合成本**（接入 + 运维 + 云端适配），不是单纯金钱：
  - `twikit` **金钱免费**，但需维护真人账号 cookie（上云后过期 = 最大运维负担）、违反 ToS、有封号风险、X 改版要跟——**工程看似省事，长跑极不省心**。
  - `twitterapi.io` **花一点钱但工程最简**：一个 `X-API-Key` header + 一个 GET 就能按用户名拉结构化推文，云端原生可达、无需任何账号维护、有免费额度可零成本试跑。对"云端长跑的直播项目"来说，这是总体拥有成本最低的。
- `tweetapi.com` 形态疑似与 `twitterapi.io` 同类（付费 API），但**两次 WebFetch + curl 均被敏感审批超时拦截，细节未拿到** → 若师傅确认它就是同类服务，则 `twitterapi.io` / `tweetapi.com` 二选一即可，优先拿到的那个。
- `twikit` / `xiaoxiunique/x-kit` 降级为**本地调试或预算为零时的备选**，不建议上云。

### 2.4 集成设计（选定 twitterapi.io 后）

```
新增 collect_x.py：
  GET https://api.twitterapi.io/twitter/user/last_tweets?userName=<handle>
  headers={"X-API-Key": os.environ["TWITTERAPI_IO_KEY"]}
  → data/x_posts.json（每账户最近 N 条、去重、带时间戳）
  → （可选）markets.py 并入 snapshot["x_posts"]
  → narrate.facts() 当"另一路快讯"喂 LLM（复用 NEWS_HINT 体系）
  → build_prompt 与 news 块并列
```
⚠️ 推特观点一律作**「外部观点 / 叙事素材」**，必须**标注来源账户与时间**，不当事实、不当预测（同受「不许编造、只引给到的」约束）。

### 5.2 推特 API 收费对比（2026-10-09 实测）
- **twitterapi.io**：按量付费、无最低消费。推文 $0.15/1K 条，1 USD=100,000 credits，单次调用最低 15 credits（$0.00015）。**定价页无真正免费档**（需购 credits）。
- **tweetapi.com**：**免费档 = 一次性 100 次请求、无需信用卡、每分钟 10 次、所有公开端点**；Pro $17/月（100K 次/月）；Ultra $57；Mega $197；PAYG $5/10,000 单位。
- **师傅假设「免费档够用」的校准**：tweetapi.com 免费档是**试用额度（一次性 100 次，不续期）**，用来验证集成零成本 OK，但**撑不住持续轮询**（若每小时抓 5 个账户 = 120 次/天，<1 天耗尽）。生产需 Pro（$17/月，100K 次远超所需）或 twitterapi.io 按量（我们低用量约 $5–6/月）。
- **结论**：先用 tweetapi.com 免费档（100 次）零成本验证集成；生产若用量低（<~5K/月）选 twitterapi.io 按量更省（$5–6 vs $17），若要可预期包月+优先支持选 tweetapi.com Pro。twikit 虽免费但需真人 cookie、违反 ToS、云端过期=运维重，排除。
