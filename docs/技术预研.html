股市直播解说 · 技术预研

把盘面、新闻、个股异动，翻译成一个解说员的口吻
目标是做「像球赛一样」的股市直播：多风格解说员可选、可模仿名人口吻、盘中实时生成。但先看清约束——难点不在 AI，而在直播流。Cloudflare 免费版无法承载真正的推流，必须换架构。
结论 可行　架构 本地生成 + CF 分发 + 客户端渲染　月成本 ¥0　建议 分三期，先做「伪直播」验证解说质量

关键认知 · 这一步不是「能不能生成」，而是「生成得够不够像球赛解说」。
需要三件事：① 事件层判断（该说哪件事）② 叙事层（比喻/悬念/情绪）③ 口语层（短句、语气词、不书面语）。
人设 = 提示词工程，做成可热更新的配置文件，多风格共存只是多份 prompt。
语音合成TTS 解说词 → 音频 ★☆☆☆☆ edge-tts 免费、免注册、中文音色自然 ¥0
edge-tts（PyPI，月下载 1300 万+）· 复用 Edge 朗读引擎，322 音色含中文 5 女 4 男，支持 SSML 调语速/音高 → 不同解说员 = 不同音色 + 不同语速。
⚠ 风险：非官方 API，2024 年曾因微软改鉴权而全线失效。建议：生成侧放在本地，接口挂掉只影响你一人，不影响线上观众。
直播流最大难点 持续推流 ★★★★★ 真直播在 CF 免费版做不到，须改伪直播 ¥0（改架构后）
为什么做不到（官方 2026-10-05 核对）· CF Workers 免费版 HTTP 请求 CPU 上限 10ms、Cron 触发 CPU 上限也是 10ms，LLM 生成（秒级）+ TTS（秒级）根本放不进去；
Workers 免费额度 10 万请求/天；KV 免费写 1000 次/天、读 10 万/天、存储 1GB、value 上限 25MiB。
WebSocket 虽支持但连接会被回收，不适合当直播流。
二 · 三种直播形态（推荐 A）
方案 做法 直播感 CF 可行性 成本
A · 伪直播推荐 本地按分钟切片生成 mp3+文本，写 KV/R2；前端按时间戳排队播，字幕逐字上屏 高（除延迟外无差别） ✅ 完全可行 ¥0
为什么 A 是正解 · 体育直播的「实时感」来自解说词跟着比赛走，不是来自视频流本身。
你的观众要的是「盘面在动 + 解说在讲」，mp3 切片 + 客户端调度即可满足，延迟 30–60 秒在财经场景完全可接受（不像竞技体育）。
零流媒体成本、零服务器推流、可随时切回真直播。
B · 真直播成本高 常驻服务器跑 WebSocket/HLS 推流 最高 ❌ 免费版不可行，需付费 Worker 或另买服务器 ¥30+ /月起
硬约束 · 免费版 Cron CPU 10ms 是决定性的——即使愿意付 $5 升级 Workers Paid，CPU 上限也只是 30 秒（可调到 5 分钟），且 Cron 频率仍受限。
真直播要另找算力：VPS / 家里的常开机器 / 或用第三方直播托管。成本与复杂度都上一个台阶。
C · 纯文字版最小验证 只有字幕流，无音频 中 ✅ 极简 ¥0
用途 · 第一期拿它验证「解说词到底像不像球赛」——这是整个项目的最大不确定性，用最便宜的方式先证伪或证实。
文字版零 TTS、零音频存储，做完不满意直接扔，成本几乎为零。

四 · 解说员人设设计（多风格 + 名人模仿）
类型 语气特征 音色 / 语速 实现方式
专业体育解说基准款 短句、节奏快、比分式播报、情绪克制 男声 · 语速 1.15x prompt + 音色绑定
脱口秀风格段子手 自嘲式吐槽、比喻夸张、有包袱 男声 · 1.3x prompt 变体
情绪化散户直播间气氛 语气词多、情绪起伏、像在跟人聊天 女声 · 1.2x prompt + SSML 调音高
名人模仿⚠ 需谨慎 「像脱口秀演员/体育明星/影视明星」 任意 见下方风险
名人模仿的合规红线 建议做「气质相似」而非「指名模仿」
具体做法：人设命名为「脱口秀腔」「老司机腔」「热血体育腔」这类风格标签，prompt 里描述语气特征而不写具体人名。既达到你要的效果，又规避「利用他人名义/形象」的法律风险（国内对声音克隆、人物形象权有明确限制）。若确实要指名，得走授权评估——这个我建议先不碰。

六 · 风险清单（诚实披露）
接口封杀（高）　今天的腾讯 WAF 封 IP 就是前车之鉴。行情源必须做三级兜底（腾讯→东财→新浪），我已有现成实现可直接复用（GS 保鲜那套）。
TTS 断供（中）　edge-tts 依赖微软非公开接口，可能随时失效。影响面可控：生成在本地，挂了只影响你，且能立刻换成 Piper/Kokoro 等本地开源模型顶上。
AI 味（高）　LLM 写解说最容易出「书面语 + 客观陈述」，完全不像球赛。这是必须反复调 prompt 的活，也是一期就要验证的核心。建议复用你已沉淀的「杨夏文风」skill 里关于「气口、跳脱、别太顺」的方法论——那套对解说同样成立。
合规（中）　名人模仿见上方红线；另需注意解说不得构成投资建议，页面固定挂「仅供研究，非投资建议」（沿用卧龙台惯例）。
时段依赖（中）　只在交易时段有内容，非交易日页面空转。建议补一个「复盘模式」——用当日 GS 本地日线生成收盘复盘解说，把空窗填上。
七 · 结论与建议
可行性 成立
成本 ¥0（全开源 + 免费额度）
建议 先做一期文字版，别急着上音频和推流
为什么可行　数据源全实测通、GS 本地库已是现成底座、CF 免费额度足够承载分发、edge-tts 免注册可用。四个环节里没有一个是死结。
为什么建议先做文字版　这个项目唯一的真风险是「解说词好不好听」，而这跟直播流、音频、CF 部署全都无关。先用半天把 prompt 调到「像球赛」，不满意就零成本止损；满意了再往上叠音频和部署，顺序反了会白花好几倍时间。
架构上唯一要守住的纪律　生成永远在本地，CF 只做分发。一旦把 LLM 调用塞进 CF Worker，就会撞上 10ms CPU 上限，到时既不能真直播、也不能伪直播，只能重写。
