## 2. 核心结论（最重要的一条）

**这个项目的技术难点不是 AI，是「直播流」在 Cloudflare 免费版根本做不了。**

- CF Workers 免费版 **Cron 触发 CPU 上限仅 10ms**（官方 docs，2026-10-05 核对）。LLM 生成（秒级）+ TTS（秒级）塞不进去。
- 即便升级 Workers Paid（$5/月），Cron CPU 上限也只到 30 秒（可配置到 5 分钟），且频率仍受限。
- WebSocket 虽支持，但连接会被回收，不适合当直播流。

**因此架构必须绕：生成永远在本地（或任意常开算力），CF 只承担静态页 + KV/R2 分发，「直播感」在客户端造。**

### 推荐架构：伪直播（方案 A）

```
① 本地生成层（卧龙台 Mac）        ② CF 分发层              ③ 客户端渲染层
   行情采集（多源兜底）    →     Pages 静态页 /live     →   伪直播时序（按时间戳排队播）
   LLM 生成解说词                 KV 存文本索引             实时字幕流（逐字上屏+滚动）
   TTS 合成 mp3（二期）             R2 存音频                 前端轮询行情直连
                                                                 人设切换（风格+音色）
```

**为什么伪直播够用**：体育直播的「实时感」来自**解说词跟着比赛走**，不是视频流本身。财经场景延迟 30–60 秒完全可接受（不像竞技体育）。**零流媒体成本，且保留升级真直播的口子（生成侧代码不用重写）。**

## 3. 全部实测数据（2026-10-05，非推测）

### 3.1 行情源 —— 三家可用，但限流是常态

| 源 | 接口 | 实测 | 备注 |
|---|---|---|---|
| **东财**（首选） | `push2.eastmoney.com/api/qt/ulist.np/get?secids=1.000001&fields=f2,f3,f12,f14` | 200，最干净 | **UTF-8 JSON**，含涨跌幅/量比/换手；异动榜 `push2 clist` 可按涨幅排序取全市场 5562 只 |
| 腾讯 | `qt.gtimg.cn/q=sh000001,sz399001` | 200，字段全 | 但 **`fqkline` 日K接口被 WAF 封**（见 §6.1） |
| 新浪 | `hq.sinajs.cn/list=sh000001` | 200，最轻量 | **GBK 编码，需转码**；Referer 必带 |

**关键教训（本次实测亲见）**：东财在 5 分钟内从"通"变成"拒"（HTTP=000 / curl rc=52 Empty reply），当时腾讯、新浪仍稳定 200。**→ 限流是常态、不是意外，任何方案都必须多源兜底。**

### 3.2 Cloudflare 免费额度（官方 docs 核对）

| 项 | 免费额度 |
|---|---|
| Workers HTTP 请求 | **10 万/天** |
| Workers HTTP CPU 时间 | **10 ms/请求** |
| Workers **Cron CPU 时间** | **10 ms**（← 致命约束） |
| Cron Wall time（墙钟） | 15 分钟 |
| KV | 读 10万/天，**写 1000/天**，存储 1GB，value ≤25MiB |
| Cron Triggers 数量 | 5 个/账号（**现有 Worker 均未配 cron，额度未占用**） |
| R2 | 10GB 免费（音频走这里） |
| 现有 Worker | `site-router`（路由）、`paywall`（付费锁+KV）、`prophet-daily` |

**注意**：LLM 调用是 `fetch()` 网络等待，**不计入 CPU 时间**——所以理论上 Cron 里调 LLM 不一定撞 10ms，但请求体组装、响应解析、写 KV 全要在这 10ms 内跑完，极限。

### 3.3 TTS

- **`edge-tts`**（PyPI，月下载 1300 万+）：免费、免注册、322 音色含中文 5 女 4 男、支持 SSML 调语速/音高 → **不同解说员 = 不同音色 + 不同语速**。LGPLv3。
- ⚠ **风险**：非公开 API（逆向微软 Edge 朗读接口），2024 年曾因微软改鉴权机制导致全线失效。
- ⚠ **影响面可控**：因为**生成在本地**，接口挂掉只影响师傅一人，不影响线上观众。
- 备选：Piper / Kokoro（本地开源，零调用成本）。

### 3.4 LLM

- ⚠ **重要**：**Cloudflare Workers AI 免费额度仅约 1000 次/天，不够盘中每分钟调用 → LLM 生成必须走外部 API**（师傅自备 key）。
- 沙箱内 WorkBuddy 自带的 LLM 能力，**不能**在 CF Worker 里用。

### 3.5 存储测算

- 盘中每 **3 分钟**一段、每段约 **20 秒** mp3（≈160KB）→ 240 段/日 ≈ **38MB/日 ≈ 1.1GB/月**
- R2 免费 10GB → 够存 **9 个月**；KV 1GB 只够 **最近 1–2 天**
- **结论：音频一律进 R2，KV 只放索引 + 文本**（每天清一次旧的）

## 4. 解说员人设设计

人设 = **提示词工程**（prompt + 音色/语速绑定），做成可热更新的配置文件，多风格共存只是多份 prompt。**不需要改引擎代码。**

| 类型 | 语气特征 | 音色/语速 |
|---|---|---|
| 专业体育解说（基准） | 短句、节奏快、比分式播报、情绪克制 | 男声 1.15x |
| 脱口秀风格 | 自嘲式吐槽、比喻夸张、有包袱 | 男声 1.3x |
| 情绪化散户 | 语气词多、情绪起伏、像在跟人聊天 | 女声 1.2x（SSML 调音高） |
| 名人模仿 | ⚠ 见下方红线 | — |

### ⚠ 名人模仿的合规红线（必须遵守）

**建议做「气质相似」而非「指名模仿」**：
- 人设命名为「脱口秀腔」「老司机腔」「热血体育腔」这类**风格标签**
- prompt 里**描述语气特征但不写具体人名**
- 效果同样达到，但规避「利用他人名义/形象」的法律风险（国内对声音克隆、人物形象权有明确限制）

若确实要指名模仿，需走授权评估 —— **建议先不碰**。

## 5. 三条路对比（待师傅拍板的核心决策）

一期（纯文字版）能否"全云端"？**能，但有前提和硬伤。**

| 方案 | 采集 | 解说词生成 | CF 可用性 | 硬伤 |
|---|---|---|---|---|
| **① 全 CF** | CF Cron 拉行情 ✅ | 接外部 LLM API | Pages+KV ✅ | **Cron CPU 10ms 撞墙**（组装/解析/写 KV 都要塞进 10ms，极限）；且 CF 拉 A 股源有被封风险 |
| **② 半云**（悟空推荐） | CF Cron 只拉行情存 KV（CPU 极小，不撞墙） | 本地 Mac 跑 LLM | ✅ | 师傅需开机（或常开） |
| **③ 免费 CI 定时** | ✅ | ✅ | 结果写 KV/Pages | **非真实时**，有分钟级延迟；Actions 免费 2000 分钟/月够用 |

### 悟空的建议顺序

1. **先做"本地验证版"（半天）** —— 纯文字，零架构成本，用来看「解说词到底像不像球赛」。这是整个项目**唯一的真不确定性**，不满意可零成本止损。
2. 满意后再上 **② 半云**（CF 常驻拉行情，师傅不用为看盘而开机）。
3. 确需"真·实时"再考虑 **CF Workers Paid（$5/月）** 或自建。

## 6. 必须知道的坑（都已踩过，别重踩）

### 6.1 腾讯 WAF 封 IP（2026-10-04 实测）
- `web.ifzq.gtimg.cn/appstock/app/fqkline/get` 返回 **HTTP 501 + `waf.tencent.com/501page.html?...-429-...`**（429=限流封禁）
- **辨别口诀**：`fqkline` 501 但 `qt.gtimg.cn`=200、baidu=200、东财有响应 → **不是网络/节点问题，是腾讯单接口封 IP**。**别去翻 Clash / 重启 WorkBuddy，那些治不了 WAF 封 IP。**
- 已在 `卧龙台/GS动量框架/momentum_a_backtest/fetch_update.py` 落地三级兜底（腾讯→东财→新浪），本项目采集层**照抄这套模式**。

### 6.2 Python stdout 块缓冲（通病）
- `print()` 写到**日志文件**时（非 TTY），Python 默认**块缓冲**，输出攒在缓冲区不实时落盘。
- **症状**：日志长时间不更新，但进程其实在正常跑。**判断前先看进程是否存活**（`pgrep`），别急着 kill。
- **修法**：关键 `print(..., flush=True)`。

### 6.3 沙箱统计大缓存会 SIGTERM
- 对 5195 个 json 做 `glob + json.load` 全量统计会被沙箱 **SIGTERM(137)**（OOM/IO）。
- **修法**：抽样 300 只 + `seek` 读文件尾估算百分比（已验证可用）。

### 6.4 复用 skeleton.html 必须处理图表块
- luxury 骨架的 `baseChart(id)` **无 null 保护** → 容器不存在时 `echarts.init(null)` 抛错，**中断整个 IIFE，连带表格排序/tab 交互全废**。
- 已在预研文档修复：`baseChart` 遇 null 返回 null + 新增 `opt()` 包装，12 处 `setOption` 全部包进 `opt()`。
- **新对话若复用骨架，务必检查这点。**

### 6.5 wrangler 登录态在沙箱会丢
- `npx wrangler whoami` 显示未登录（沙箱重开会话丢失）。**部署前需师傅在沙箱外跑一次 `wrangler login`**，或用 `wrangler deploy --temporary` 临时预览账号。

### 6.6 跑批脚本在启动台的硬超时
- 启动台每个 task step 有硬超时，超时杀整个进程组返回 124。**长跑任务须在 `registry.json` 显式放大 `timeout`**（`gsrefresh` = 10800 即 180 分钟）。
