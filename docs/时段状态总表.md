## 1. 两层判定（先分清，否则一定会误判）

| 层 | 问题 | 依据 | 代码 |
|---|---|---|---|
| **钟点层** | 这个钟点**该不该**开？ | 各交易所交易时间表（北京时间） | `MARKET_SEGS` → `_state_of()` |
| **日级层** | 今天**到底**开没开？ | 行情源最后报价时刻的陈旧度 | `market_state()` 的 `traded_today` / `holiday` |

日级层为什么必须存在：**节假日/周末/台风停市 = 行情源会一直停在「上一交易日的报价时刻」**。
这个陈旧度就是铁证，比自建节假日表更硬（无需年度维护，还能覆盖台风停市这类日历外的休市）。
实测 2026-10-06 A股报价停在 09-30 16:19 → 国庆休市；同日港股报价 11:21:42 → 正常交易。

⚠️ **陈旧度只对「常规交易(open)段」生效**。盘前/盘后本就是无连续 tick 的时段，
用新鲜度判会误杀——旧口径会把「A股盘前 + 陈旧报价」压成休市，直接导致 08:00–09:30 显示「全场休息」。

## 2. 状态码字典

| 状态码 | 文案 | 含义 | 亮灯（ON AIR 呼吸灯） |
|---|---|---|---|
| `open` | 交易中 | 常规交易时段，场内有连续报价 | ✅ 亮 |
| `pre` | 盘前 | 开盘前时段（A股 08:00–09:30 / 美股 16:00 或 17:00 起） | ❌ 灭 |
| `post` | 盘后 | 收盘后时段（美股 04:00–08:00，冬令时 05:00–08:00） | ❌ 灭 |
| `closed` | 休市 | 该市场此刻无场次（含午休、盘前盘后之外的时段） | ❌ 灭 |

> 呼吸灯只由「任一市场 `open`」决定；**灯灭 ≠ 没节目**（盘前/盘后照常有解说场）。

`active`（当前主角）的优先级：**常规交易 > 盘前 > 盘后 > 全休息**；并列时按 `A股 → 港股 → 美股`。

## 4.5 周末与节假日（日级层压制规则，V1.9.28 补）

上面 §3/§4 的全表是**工作日（周一～周五）**口径。周末与工作日节假日属于「日级层」的额外压制，
不改变钟点层，但会改写最终状态。

### 周末（周六 / 周日）

A股、港股**周六周日恒休市**，与报价是否新鲜无关——因此 `market_state()` 在周末对 `cn`/`hk`
**强制** `closed + holiday=True`（即使时钟段 09:30–15:00 命中，也直接压掉）。

⚠️ **美股不在此列**：其常规段 21:30–次日 04:00 跨到北京周六 00:00–04:00，本就是**真实盘中**
（美东周五常规段），必须保留时钟判定。所以周末判定只对 `cn`/`hk` 生效，美股按钟点层原样跑。

| 北京时间（周末） | 主角 | 状态 | 说明 |
|---|---|---|---|
| 00:00 – 04:00 | 美股 | 交易中 | us: open（美东周五常规段跨北京周六晨） |
| 04:00 – 08:00 | 美股 | 盘后 | us: post |
| 08:00 – 09:30 | — | 周末休市 | cn/hk 全压 closed；美股盘前未开 |
| 09:30 – 12:00 | — | 周末休市 | 即便钟点层 cn/hk 命中 09:30，也被强制 closed |
| 12:00 – 13:00 | — | 午间休市（空档名沿用） | 与工作日同名的空档 |
| 13:00 – 16:00 | — | 周末休市 | cn/hk 压 closed |
| 16:00 – 21:30 | 美股（夏令）/ —（冬令 16–17 空档） | 盘前 / 场次交接 | us: pre（冬令时 16–17 仍空档） |
| 21:30 – 24:00 | 美股 | 交易中 | us: open |

**空档命名在周末**：命中 `IDLE_WINDOWS`（12:00–13:00）→ 仍显示「午间休市」；
其余非交易时段 → 显示「**周末休市**」（V1.9.28 新增，替代笼统的「全场休息」）。
> 注：周末凌晨 00:00–04:00 美股在播时 `active=us`，徽标显示「美股 · 交易中」，不进入空档命名路径。

### 工作日节假日（春节 / 国庆 / 台风停市等）

仍走 §1 日级层逻辑：行情源报价停在「上一交易日」→ `traded_today=False` 且时钟判 `open`
→ 覆盖为 `closed + holiday=True`。该路径在 V1.9.28 改为 `elif`（仅工作日生效），周末走上方独立分支。
实测：2026-10-06 A股报价停在 09-30 16:19 → 国庆休市，被正确压成「交易中→休市」。

| 空档 | 名称 | 副文案 | 出现条件 |

## 6. UI 呈现规则

| 位置 | 数据源 | 刷新 |
|---|---|---|
| 导播台徽标（ON AIR · 状态） | `active_names` + `active_status`；空档用 `idle_name` + `idle_note` | `/__session__.json` 每 4s 现算 |
| 24h 时段条（三轨） | 各市场 `segs`（含 dst 平移后的端点） | 同上 |
| 呼吸灯 | 任一市场 `state == "open"` | 同上 |

页面上烙入的 session 只是**首屏兜底**；`/__session__.json` 会每 4s 用「当前钟点现算」覆盖它。
所以开盘/午休/收盘这类分钟级边界不会滞后（一轮 300s + 采集 2min，最长会差 7 分钟）。

## 8. ⚠️ 运维铁律：改 `markets.py` 必须重启观看服务

`serve_live.py` 是**常驻进程**，启动时就把 `markets` 模块加载进内存。
Python 的模块缓存意味着：**改完 `markets.py` 后不重启，`/__session__.json` 会一直返回旧逻辑**，
页面每 4s 拉一次现算结果、反而会用旧值覆盖掉新构建的页面。

实测教训（2026-10-09）：A股盘前段加好后，页面 09:05 仍显示「全场休息」——
`live.html`（09:02 构建）里烙的已经是「A股 · 盘前」，但 `/__session__.json` 由 08:51 启动的旧进程提供，
`cn.segs` 里还没有盘前段。

```bash
python3 start_server.py restart     # 改 markets.py / 时段逻辑后必做
python3 start_server.py status      # 确认 PID 与端口
```

（`live.html` / `build_live.py` 的改动**不需要**重启：循环每轮起新子进程，自然加载新代码。）
